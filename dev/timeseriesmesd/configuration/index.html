DEFAULT_PRESSURE_LEVELS

Default output pressure levels (hPa) by planet, used by PressureLevels when no levels are given. The key is the lower-case planet name, i.e. the lower-case name of the PlanetCalendar of the configuration ("mars" for MARS_CALENDAR). Further planets can be added with DEFAULT_PRESSURE_LEVELS["<planet>"] = [...].

PlanetPostStats.TimeSeriesMeSd.DerivedVariable — Type
DerivedVariable(name, sources, combine; units, long_name, to_pressure=true)

A variable computed from already loaded variables (input or earlier derived variables) after reading, e.g. the accumulated dust mass mixing ratio over several size bins.

combine is called as combine(a₁, a₂, …) with the arrays of the variables named in sources (in that order; Float32, dimensions lon × lat [× level] × time, missing values NaN32) and must return an array of the same size. Derived variables are evaluated in the order of TimeSeriesConfig.derived, so a derived variable may use previously derived ones. All sources must have the same dimensionality.

Two helper constructors for combine are provided: sum_of and, for a whole chain of accumulated sums, cumulative_sums.

Arguments

  • name::AbstractString: output variable name (must be unique).
  • sources::AbstractVector{<:AbstractString}: names of the variables combined.
  • combine: function of length(sources) arrays.

Keyword arguments

  • units::AbstractString = "": units of the result; empty → units of the first source.
  • long_name::AbstractString = name: descriptive name.
  • to_pressure::Bool = true: for a 3D result, whether it is interpolated to pressure levels when TimeSeriesConfig.pressure_levels is set (see InputVariable).

Example

julia> d = DerivedVariable("ClaySilt1", ["Clay", "Silt1"], sum_of(); units="kg kg-1",
                           long_name="Dust mass mixing ratio, clay + silt bin 1");

julia> d.combine(fill(1f0, 2, 2), fill(2f0, 2, 2))
2×2 Matrix{Float32}:
 3.0  3.0
 3.0  3.0

InputGroup(product::AbstractString, variables::AbstractVector{InputVariable})

A scaleacc output product (e.g. "aij", "aijl", "taijl") and the variables to be read from its monthly files. One monthly file per product is expected for every month of the simulation period; the file name is constructed by TimeSeriesConfig.filename (default scaleacc_filename).

PlanetPostStats.TimeSeriesMeSd.InputVariable — Type
InputVariable(name; scale=1.0, units="", long_name="", to_pressure=true)

A variable to be read from a scaleacc output product (see InputGroup).

scaleacc stores many quantities in scaled units, given in the units attribute (e.g. tracer mixing ratios in units of 1e-8 kg kg⁻¹). After reading, values are multiplied by scale, so that the internal and the output data are in the units units; values and units attribute of the output files are consistent.

Any scale_factor/add_offset/_FillValue/missing_value attributes of the input file are applied by NCDatasets when reading (CF decoding) before scale is applied.

Arguments

  • name::AbstractString: variable name in the scaleacc file (e.g. "prsurf").

Keyword arguments

  • scale::Real = 1.0: multiplicative factor converting file values to units.
  • units::AbstractString = "": units after scaling; empty → taken from the file's units attribute (only sensible if scale == 1).
  • long_name::AbstractString = "": descriptive name; empty → the file's long_name.
  • to_pressure::Bool = true: for a 3D variable, whether it is interpolated to pressure levels when TimeSeriesConfig.pressure_levels is set (see PressureLevels). Set it to false for quantities that are integrals over a model layer (e.g. the air mass per layer in kg m⁻²), which have no meaning at a pressure level; such variables stay on the model levels. Ignored for 2D variables.

Example

julia> v = InputVariable("Clay"; scale=1e-8, units="kg kg-1");

julia> v.scale, v.to_pressure
(1.0e-8, true)

julia> InputVariable("airmass"; units="kg m-2", to_pressure=false).to_pressure
false

PlanetPostStats.TimeSeriesMeSd.PressureLevels — Type
PressureLevels(levels=nothing; surface_pressure="prsurf", mode=:add)

Interpolation of the 3D variables from the hybrid σ–pressure model layers of ModelE/ROCKE-3D to pressure levels in the output (see interpolate_to_pressure for the method). Set as TimeSeriesConfig.pressure_levels; requires TimeSeriesConfig.vertical (VerticalCoordinate) and the reference mid-layer pressures plm in the input files.

Choice of the levels:

  • levels = nothing (default): the default levels of the planet of the configuration (default_pressure_levels of TimeSeriesConfig.calendar.name, e.g. the 43 Mars levels of DEFAULT_PRESSURE_LEVELS for MARS_CALENDAR);
  • levels = :model: the reference mid-layer pressures plm of the input files, i.e. the pressures of the model layers in a column with surface pressure VerticalCoordinate.psf;
  • a vector of pressures: these levels.

The levels in use are returned by output_pressure_levels, the pressures at the edges of their layers (written as plev_bnds) by output_pressure_bounds: for levels = :model, the reference edge pressures of the model layers (Psf and the upper-edge pressures ple of the input files) if ple is present in the input files; otherwise, and for all other levels, the midpoints in ln p between the levels (pressure_level_bounds).

The interpolation is done on the monthly means of each column, using the monthly mean surface pressure of the column, before any temporal or spatial averaging. All products (time series, multi-year statistics; gridded, zonal, and global means) are then computed on the pressure levels. Pressure levels below the local surface are missing, so zonal and global means at high pressures cover only the area above the surface and are subject to TimeSeriesConfig.threshold.

Variables with to_pressure = false (InputVariable, DerivedVariable) and 2D variables are not interpolated.

Arguments

  • levels = nothing: pressure levels in hPa (the unit of the surface pressure and of plm), any order, positive and unique; written as coordinate plev in the given order. nothing: default levels of the planet; :model: reference mid-layer pressures plm of the input files.

Keyword arguments

  • surface_pressure::AbstractString = "prsurf": name of the 2D surface-pressure variable (hPa) among the configured variables.
  • mode::Symbol = :add:
    • :add — the model-level output is written as without pressure levels, and the interpolated variables are written in addition to separate files with the tags ijp, zmp, gmp;
    • :replace — the interpolated variables are written on pressure levels instead of model levels into the regular files; 3D variables with to_pressure = false stay on model levels in the same files.

Example

julia> pl = PressureLevels();                        # planet default

julia> pl.levels === nothing, pl.mode
(true, :add)

julia> PressureLevels([6.0, 5.0, 4.0, 3.0, 2.0, 1.0, 0.5, 0.1]; mode=:replace).levels[1]
6.0

julia> PressureLevels(:model).levels                # model reference levels plm
:model

PlanetPostStats.TimeSeriesMeSd.TimeSeriesConfig — Type
TimeSeriesConfig(; kwargs...)

Complete, user- and simulation-specific configuration of the time-series and statistics post-processing performed by run_timeseries_statistics.

Required keyword arguments

  • simpath::AbstractString: directory containing one subdirectory per run.
  • runs::AbstractVector{<:AbstractString}: run identifiers; input files of run r are expected in joinpath(simpath, r, postdir).
  • sim_period::Tuple{YearMonth,YearMonth}: first and last month of the input files. Runs may end earlier; the record of each run ends with the last month for which at least one input file exists.
  • stat_period::Tuple{YearMonth,YearMonth}: window for the multi-year statistics. Only periods (years, seasons) lying entirely inside the window are used.
  • output_dir::AbstractString: name of the output directory created in every run directory (e.g. "Tracermass3d").
  • output_name::AbstractString: tag used in output file names (e.g. "tracermass3d").

Optional keyword arguments

  • groups = InputGroup[]: scaleacc products and variables to read; required (non-empty) for run_timeseries_statistics. Applications that provide their own input (e.g. PlanetPostStats.DustOptics) leave it empty.
  • postdir = "Post": subdirectory of a run directory with the scaleacc files.
  • output_root = nothing: if given, output goes to joinpath(output_root, run, output_dir) instead of joinpath(simpath, run, output_dir).
  • derived = DerivedVariable[]: variables computed after reading (see DerivedVariable, cumulative_sums).
  • calendar = EARTH_NOLEAP_CALENDAR: PlanetCalendar.
  • seasons = EARTH_SEASONS: vector of SeasonSpec.
  • time_axis = TimeAxis(): numerical time coordinate, see TimeAxis.
  • vertical = nothing: VerticalCoordinate of the model layers; written as metadata to 3D output and needed for pressure_levels.
  • pressure_levels = nothing: PressureLevels for the interpolation of the 3D variables to pressure levels; nothing → output on model levels only.
  • threshold = 80.0: validity threshold in percent (see module documentation).
  • weight_seasons = true: weight months by their length in seasonal means, as in annual means (on Mars the month lengths range from 46 to 66 sols); false gives equal weights to the months of a season.
  • products = ALL_PRODUCTS: subset of ALL_PRODUCTS to compute and write.
  • representations_3d = [:ij, :zm, :gm]: spatial representations written for variables with a vertical dimension (on model or pressure levels), a non-empty subset of :ij (gridded), :zm (zonal mean), and :gm (global mean); e.g. [:zm, :gm] writes only their zonal and global means, which saves most of the disk space. Variables without a vertical dimension are always written in all three representations. Files that would contain no variable are not created, and the tags of the files follow their content (e.g. *.ij.mts.nc instead of *.ijl.mts.nc if the gridded files contain only 2D variables). Keep :ij for the monthly dust tracer time series that are the input of PlanetPostStats.DustOptics (*.ijl.mts.nc).
  • fill_value = -1f30: value written for missing data (_FillValue).
  • area_variable = "axyp": name of the grid-cell area variable in the input files (the output files always call it axyp).
  • global_attributes = OrderedDict{String,Any}(): global attributes of all output files (the attributes Experiment and File_creation_time are added per file).
  • filename = nothing: function (ym, product, run) -> String giving the input file name; nothing → scaleacc_filename.
  • deflatelevel = 0: NetCDF-4 compression level (0 … 9) of the output variables.
  • overwrite = true: overwrite existing output files; if false, an existing file raises an error.

Example

cfg = TimeSeriesConfig(;
    simpath="/path/to/simulations",
    runs=["MarsDustRun1"],
    groups=[InputGroup("aij", [InputVariable("prsurf"; units="hPa")])],
    sim_period=(YearMonth(1, 1), YearMonth(20, 12)),
    stat_period=(YearMonth(3, 1), YearMonth(20, 12)),
    calendar=MARS_CALENDAR,
    seasons=MARS_SEASONS,
    output_dir="Prsurf",
    output_name="prsurf",
)
validate_config(cfg)

PlanetPostStats.TimeSeriesMeSd.VerticalCoordinate — Type
VerticalCoordinate(ls1::Integer, psf::Real, ptop::Real)

Parameters of the hybrid sigma–pressure vertical coordinate of ModelE/ROCKE-3D, written as scalar metadata variables LS1, Psf, and Ptop to all files containing 3D variables.

Below layer ls1 the coordinate is σ with σₑ = (pₑ − ptop)/(psf − p_top).

Arguments

  • ls1: first layer of pure pressure coordinates above the σ layers.
  • psf: global mean surface pressure used for the σ definition (hPa).
  • ptop: pressure at the bottom of layer ls1 (hPa).

Example

julia> vc = VerticalCoordinate(31, 6.86, 0.2);

julia> vc.ls1
31

PlanetPostStats.TimeSeriesMeSd.cumulative_sums — Method
cumulative_sums(sources; names, long_names=names, units="") -> Vector{DerivedVariable}

Convenience constructor of a chain of accumulated sums, e.g. over size bins: for sources = [s₁, s₂, …, sₙ] it returns n - 1 derived variables

names[1] = s₁ + s₂,  names[2] = s₁ + s₂ + s₃,  …,  names[n-1] = s₁ + … + sₙ.

Each derived variable is defined as the previous one plus the next bin, so that the total work is linear in n.

Arguments

  • sources::AbstractVector{<:AbstractString}: names of the size-bin variables, ordered from the smallest to the largest bin (length(sources) ≥ 2).

Keyword arguments

  • names: n - 1 names of the accumulated variables.
  • long_names = names: n - 1 descriptive names.
  • units = "": units (empty → units of sources[1]).

Example

julia> ds = cumulative_sums(["Clay", "Silt1", "Silt2"];
                            names=["Clay_Silt1", "Clay_Silt2"], units="kg kg-1");

julia> [(d.name, d.sources) for d in ds]
2-element Vector{Tuple{String, Vector{String}}}:
 ("Clay_Silt1", ["Clay", "Silt1"])
 ("Clay_Silt2", ["Clay_Silt1", "Silt2"])

PlanetPostStats.TimeSeriesMeSd.dust_mass_classes — Method
dust_mass_classes(available; physvar="", addlongname="", units="") -> Vector{DerivedVariable}

Cumulative dust mass size classes of ModelE/ROCKE-3D, with the bin and class names of PlanetTools.DerivePhysicsVariables.accumulate_dust_masses_modele:

classsum of the bins
PM2DustClay
PM4DustClay + Silt1
PM8DustClay + Silt1 + Silt2
PM16Dust… + Silt3
PM32Dust… + Silt4
PM64Dust… + Silt5

The bin variables are named <bin><physvar> and the classes <class><physvar>. As in PlanetTools, the accumulation stops at the first bin not contained in available, so only complete classes are created. The long name of a class is "<class> <addlongname>" (or "<class>"), the units are those of Clay<physvar> unless units is given.

The bins and classes are taken from PlanetTools, so both packages stay consistent.

Arguments

  • available: names of the variables that will be loaded, typically [v.name for g in groups for v in g.variables].

Keyword arguments

  • physvar::AbstractString = "": suffix of the bin names (e.g. "_emission").
  • addlongname::AbstractString = "": text appended to the class name in long_name.
  • units::AbstractString = "": units of the classes (empty → units of the clay bin).

Example

julia> ds = dust_mass_classes(["Clay", "Silt1", "Silt2", "Silt3", "Silt4"]);

julia> [(d.name, d.sources) for d in ds][1:3]
3-element Vector{Tuple{String, Vector{String}}}:
 ("PM2Dust", ["Clay"])
 ("PM4Dust", ["PM2Dust", "Silt1"])
 ("PM8Dust", ["PM4Dust", "Silt2"])

PlanetPostStats.TimeSeriesMeSd.validate_config — Method
validate_config(cfg::TimeSeriesConfig; names=variable_names(cfg), require_groups=true)
    -> TimeSeriesConfig

Checks a configuration for consistency and throws an ArgumentError describing the first problem found. Checks: non-empty runs and (if require_groups) groups; unique variable names; sources of derived variables defined before use; valid simulation and statistics periods, with the statistics window overlapping the simulation period; threshold in (0, 100]; known products; known, unique, non-empty representations_3d; deflatelevel in 0:9; for pressure_levels, a vertical coordinate, default levels for the planet if no levels are given, and a configured surface-pressure variable; no reserved names (lon, lat, level, plev, time, year, month, plm, ple, area variable, axyp, Dates, LS1, Psf, Ptop) used as variable names. Returns cfg so that it can be chained.

Keyword arguments

  • names = variable_names(cfg): names of the variables of the application, checked for uniqueness and reserved names, and searched for the surface-pressure variable of pressure_levels. Applications with their own input pass their variable names here.
  • require_groups = true: whether cfg.groups must be non-empty.

Example

julia> validate_config(cfg);  # throws if cfg is inconsistent

julia> validate_config(cfg; names=["effRad3d_PM32Dust", "prsurf"], require_groups=false);
