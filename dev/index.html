PlanetPostStats.PlanetPostStats — Module
PlanetPostStats

Statistical post-processing of output from the GISS post-processing program scaleacc, which converts the accumulation (acc) files of NASA GISS ModelE and ROCKE-3D simulations into monthly NetCDF files (e.g. the aij, aijl, taijl products).

The package is organized into submodules, one per post-processing task. Each submodule receives all simulation- and user-specific information (paths, run identifiers, variables, calendars, seasons, time windows, metadata) as function arguments, so that no source code has to be edited when the post-processing is applied to a different set of simulations or by a different user.

Submodules

  • TimeSeriesMeSd: extraction of monthly, seasonal, and annual time series of gridded (ij), zonal-mean (zm), and global-mean (gm) fields from a set of simulations, and calculation of multi-year means and standard deviations of annual means, seasonal means, and the individual months of the annual cycle within a selectable time window. All results are written to NetCDF files.

Further submodules for other post-processing tasks are meant to be added as src/<SubmoduleName>/<SubmoduleName>.jl and included below.

Example

using PlanetPostStats
using PlanetPostStats.TimeSeriesMeSd

cfg = TimeSeriesConfig(;
    simpath="/path/to/simulations",
    runs=["MarsDustRun1"],
    groups=[InputGroup("aij", [InputVariable("prsurf"; units="hPa")])],
    sim_period=(YearMonth(1, 1), YearMonth(20, 12)),
    stat_period=(YearMonth(3, 1), YearMonth(20, 12)),
    calendar=MARS_CALENDAR,
    seasons=MARS_SEASONS,
    output_dir="Prsurf",
    output_name="prsurf",
)
results = run_timeseries_statistics(cfg)

PlanetPostStats.TimeSeriesMeSd — Module
TimeSeriesMeSd

Submodule of PlanetPostStats that turns monthly scaleacc output of one or more ModelE/ROCKE-3D simulations into

  1. monthly mean time series (mts),
  2. annual mean time series (ats) of full calendar years,
  3. seasonal mean time series (sts), one series per season,
  4. multi-year means and standard deviations of the annual means (moa, soa),
  5. multi-year means and standard deviations of the seasonal means (mos, sos),
  6. multi-year means and standard deviations of every month of the annual cycle (mom, som),

each of them for three spatial representations:

  • ij — the gridded field (longitude × latitude [× level]),
  • zm — the area-weighted zonal mean (latitude [× level]),
  • gm — the area-weighted global mean ([level]).

Two-dimensional (lon × lat) and three-dimensional (lon × lat × level) variables can be mixed; they are written into the same files. Files containing at least one 3D variable get the representation tags ijl, zml, gml (e.g. *.ijl.mts.nc), files with only 2D variables get ij, zm, gm.

Optionally (PressureLevels), 3D variables are interpolated from the hybrid σ–pressure model layers to pressure levels (linear in ln p, missing below the surface), either into additional files with the tags ijp, zmp, gmp or in place of the model-level fields.

Workflow

All settings that may differ between simulations or users are collected in a TimeSeriesConfig. The single entry point run_timeseries_statistics then processes every run listed in the configuration one run at a time (bounded memory), and returns a vector of RunResults containing the paths of the written files and small summary tables of global means for interactive inspection.

Treatment of missing data

All statistics are computed with PlanetTools.PlanetStatistics (see the adapters in statistics.jl), so the definitions are those of PlanetTools. Missing data are NaN32. One validity threshold threshold (percent, TimeSeriesConfig.threshold, default 80) applies to every step:

  • zonal means: equal-weight mean over the valid longitudes, valid if at least threshold % of the longitudes are valid (availability = valid fraction);
  • global means: area-weighted, valid if at least threshold % of the area is valid (availability = valid area fraction);
  • annual and seasonal means: month weights (month length, see weight_seasons) times the availability of the input month; valid if at least threshold % of the months of the period are valid (availability = fraction of valid months);
  • multi-year statistics (moa/soa, mos/sos, mom/som): availability-weighted mean and sample standard deviation (Σw(x − μ)² / (V₁ − V₂/V₁), i.e. n − 1 for equal weights), weights = availabilities of the annual/seasonal means (or of the monthly zonal/global means); valid if at least threshold % of the samples are valid; the standard deviation needs at least two valid samples.

Output files are written with PlanetTools.ReadWritePlanet.writenetcdf. Invalid results are NaN32 in memory and the fill value (TimeSeriesConfig.fill_value, default -1f30) in the output files, with a matching _FillValue attribute.

Example

using PlanetPostStats.TimeSeriesMeSd

cfg = TimeSeriesConfig(;
    simpath="/path/to/simulations",
    runs=["MarsDustRun1"],
    groups=[
        InputGroup("aij", [InputVariable("prsurf"; units="hPa")]),
        InputGroup("taijl", [InputVariable("Clay"; scale=1e-8, units="kg kg-1")]),
    ],
    sim_period=(YearMonth(1, 1), YearMonth(20, 12)),
    stat_period=(YearMonth(3, 1), YearMonth(20, 12)),
    calendar=MARS_CALENDAR,
    seasons=MARS_SEASONS,
    output_dir="Tracermass3d",
    output_name="tracermass3d",
)
results = run_timeseries_statistics(cfg)
annual_summary(results)

PlanetPostStats.TimeSeriesMeSd.DerivedVariable — Type
DerivedVariable(name, sources, combine; units, long_name, to_pressure=true)

A variable computed from already loaded variables (input or earlier derived variables) after reading, e.g. the accumulated dust mass mixing ratio over several size bins.

combine is called as combine(a₁, a₂, …) with the arrays of the variables named in sources (in that order; Float32, dimensions lon × lat [× level] × time, missing values NaN32) and must return an array of the same size. Derived variables are evaluated in the order of TimeSeriesConfig.derived, so a derived variable may use previously derived ones. All sources must have the same dimensionality.

Two helper constructors for combine are provided: sum_of and, for a whole chain of accumulated sums, cumulative_sums.

Arguments

  • name::AbstractString: output variable name (must be unique).
  • sources::AbstractVector{<:AbstractString}: names of the variables combined.

Keyword arguments

  • units::AbstractString = "": units of the result; empty → units of the first source.
  • long_name::AbstractString = name: descriptive name.
  • to_pressure::Bool = true: for a 3D result, whether it is interpolated to pressure levels when TimeSeriesConfig.pressure_levels is set (see InputVariable).

julia> d = DerivedVariable("ClaySilt1", ["Clay", "Silt1"], sum_of(); units="kg kg-1",
                           long_name="Dust mass mixing ratio, clay + silt bin 1");

PlanetPostStats.TimeSeriesMeSd.InputVariable — Type
InputVariable(name; scale=1.0, units="", long_name="", to_pressure=true)

A variable to be read from a scaleacc output product (see InputGroup).

scaleacc stores many quantities in scaled units, given in the units attribute (e.g. tracer mixing ratios in units of 1e-8 kg kg⁻¹). After reading, values are multiplied by scale, so that the internal and the output data are in the units units; values and units attribute of the output files are consistent.

Any scale_factor/add_offset/_FillValue/missing_value attributes of the input file are applied by NCDatasets when reading (CF decoding) before scale is applied.

Arguments

  • name::AbstractString: variable name in the scaleacc file (e.g. "prsurf").

Keyword arguments

  • scale::Real = 1.0: multiplicative factor converting file values to units.
  • units::AbstractString = "": units after scaling; empty → taken from the file's units attribute (only sensible if scale == 1).
  • long_name::AbstractString = "": descriptive name; empty → the file's long_name.
  • to_pressure::Bool = true: for a 3D variable, whether it is interpolated to pressure levels when TimeSeriesConfig.pressure_levels is set (see PressureLevels). Set it to false for quantities that are integrals over a model layer (e.g. the air mass per layer in kg m⁻²), which have no meaning at a pressure level; such variables stay on the model levels. Ignored for 2D variables.

Example

julia> v = InputVariable("Clay"; scale=1e-8, units="kg kg-1");

julia> v.scale, v.to_pressure
(1.0e-8, true)

julia> InputVariable("airmass"; units="kg m-2", to_pressure=false).to_pressure
false

PlanetPostStats.TimeSeriesMeSd.PressureLevels — Type
PressureLevels(levels=nothing; surface_pressure="prsurf", mode=:add)

Interpolation of the 3D variables from the hybrid σ–pressure model layers of ModelE/ROCKE-3D to pressure levels in the output (see interpolate_to_pressure for the method). Set as TimeSeriesConfig.pressure_levels; requires TimeSeriesConfig.vertical (VerticalCoordinate) and the reference mid-layer pressures plm in the input files.

Without levels (nothing), the default levels of the planet of the configuration are used (default_pressure_levels of TimeSeriesConfig.calendar.name, e.g. the 43 Mars levels of DEFAULT_PRESSURE_LEVELS for MARS_CALENDAR); explicit levels override the default. The levels in use are returned by output_pressure_levels.

The interpolation is done on the monthly means of each column, using the monthly mean surface pressure of the column, before any temporal or spatial averaging. All products (time series, multi-year statistics; gridded, zonal, and global means) are then computed on the pressure levels. Pressure levels below the local surface are missing, so zonal and global means at high pressures cover only the area above the surface and are subject to TimeSeriesConfig.threshold.

Variables with to_pressure = false (InputVariable, DerivedVariable) and 2D variables are not interpolated.

Arguments

  • levels = nothing: pressure levels in hPa (the unit of the surface pressure and of plm), any order, positive and unique; written as coordinate plev in the given order. nothing: default levels of the planet.

Keyword arguments

  • surface_pressure::AbstractString = "prsurf": name of the 2D surface-pressure variable (hPa) among the configured variables.
  • mode::Symbol = :add:
    • :add — the model-level output is written as without pressure levels, and the interpolated variables are written in addition to separate files with the tags ijp, zmp, gmp;
    • :replace — the interpolated variables are written on pressure levels instead of model levels into the regular files; 3D variables with to_pressure = false stay on model levels in the same files.

Example

julia> pl = PressureLevels();                        # planet default

julia> pl.levels === nothing, pl.mode
(true, :add)

julia> PressureLevels([6.0, 5.0, 4.0, 3.0, 2.0, 1.0, 0.5, 0.1]; mode=:replace).levels[1]
6.0

PlanetPostStats.TimeSeriesMeSd.interpolate_to_pressure — Method
interpolate_to_pressure(x, ps, plm, vc, plev) -> Array{Float32,4}

Interpolates the monthly 3D field x from the model layers to the pressure levels plev.

For every column and month, the mid-layer pressures p₁ > p₂ > … > p_L of the model layers are computed from the surface pressure ps of that column and month with layer_pressure. For a pressure level P:

  • P > ps (below the local surface): missing (NaN32);
  • ps ≥ P ≥ p₁ (between the surface and the mid-point of the lowest layer): value of the lowest layer;
  • p_l ≥ P ≥ p_{l+1}: linear interpolation in ln p between layers l and l + 1, x = x_l + (ln P − ln p_l) / (ln p_{l+1} − ln p_l) · (x_{l+1} − x_l);
  • P < p_L (above the mid-point of the uppermost layer): missing.

The result is missing where a value of the two bracketing layers or the surface pressure is missing. The loop over the columns is multi-threaded.

Arguments

  • x::AbstractArray{<:Real,4}: field (lon, lat, layer, time), layer 1 at the bottom; missing values NaN.
  • ps::AbstractArray{<:Real,3}: surface pressure (lon, lat, time), same unit as plm and plev (hPa).
  • plm::AbstractVector{<:Real}: reference mid-layer pressures of the layers.
  • vc::VerticalCoordinate: parameters of the vertical coordinate.
  • plev::AbstractVector{<:Real}: target pressure levels.

Returns

Array{Float32,4} of size (lon, lat, length(plev), time).

PlanetPostStats.TimeSeriesMeSd.multiyear_stats — Method
multiyear_stats(x, x_w, slots; threshold=80.0, corrected=true) -> (mean, sd, avail)

Multi-year mean and standard deviation over the contiguous samples slots (last dimension of x, e.g. the annual or seasonal means of the years in the statistics window), computed with PlanetTools.PlanetStatistics.calc_multiyear_stats! (Val(:annual)).

Definitions (PlanetTools): with the availabilities x_w as weights w of the valid samples, V₁ = Σw, V₂ = Σw², the mean is μ = Σwx / V₁ and the standard deviation

  • corrected=true (default): σ = √(Σw(x − μ)² / (V₁ − V₂/V₁)), the sample standard deviation for reliability weights, √(Σ(x − μ)² / (n − 1)) for equal weights; NaN with fewer than two valid samples;
  • corrected=false: the population standard deviation √(Σw(x − μ)² / V₁).

Results are NaN if fewer than threshold percent of the samples are valid; avail is the fraction of valid samples.

Arguments

  • x::AbstractArray{<:Real}: samples along the last dimension.
  • x_w: availability weights of x (same size) or nothing (equal weights).
  • slots::AbstractUnitRange{<:Integer}: indices of the samples to use.

Keyword arguments

  • threshold::Real = 80.0: minimum percentage of valid samples.
  • corrected::Bool = true: sample (true) or population (false) standard deviation.

PlanetPostStats.TimeSeriesMeSd.run_timeseries_statistics — Method
run_timeseries_statistics(cfg::TimeSeriesConfig; runs=cfg.runs) -> Vector{RunResult}

Main entry point. Validates cfg and processes every run in runs (default: all runs of the configuration) sequentially:

  1. load_run reads the monthly scaleacc files and evaluates derived variables.
  2. With cfg.pressure_levels, the 3D variables with to_pressure = true are interpolated to pressure levels (interpolate_to_pressure), one variable at a time, and assigned to the output files (output_entries).
  3. For every variable, the monthly gridded field (ij), its zonal mean (zm), and its global mean (gm) are formed (planet_means); for each of the three, the requested products of ALL_PRODUCTS are computed (annual_means, seasonal_means, multiyear_stats, monthly_stats, all built on PlanetTools.PlanetStatistics) and written immediately, so that only one variable's results are held in memory.
  4. The run's data are released before the next run is loaded.

Output directory of run r: output_directory(cfg, r), with subdirectories MonthlyTs, AnnualTs, SeasonalTs, AnnualMeSd, SeasonalMeSd, MonthlyMeSd.

Statistics are computed only from periods lying entirely in cfg.stat_period; products for which no such period exists in a run (e.g. a run shorter than the window) are skipped with a warning.

Arguments

  • cfg::TimeSeriesConfig: configuration.

Keyword arguments

  • runs = cfg.runs: subset of runs to process.

Returns

Vector{RunResult}, one per run, with written file paths and summary tables (see annual_summary, seasonal_summary).

Example

using PlanetPostStats.TimeSeriesMeSd
results = run_timeseries_statistics(cfg)
annual_summary(results)
