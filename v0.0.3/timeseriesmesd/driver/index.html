PlanetPostStats.TimeSeriesMeSd.OutputEntry — Type
OutputEntry

One variable as written to one set of output files.

Fields

  • fileset::Symbol: :main (regular files) or :pressure (additional files on pressure levels, PressureLevels(…; mode=:add)).
  • name::String: variable name.
  • attrib::OrderedDict{String,Any}: output attributes.
  • vertical::Symbol: :none (2D), :model (model levels), or :pressure.
  • data::Function: function without arguments returning the monthly field; for pressure levels it performs the interpolation, so that interpolated fields exist only while the variable is processed.

Example

entries = output_entries(cfg, load_run(cfg, "MarsDustRun1"))
[(e.fileset, e.name, e.vertical) for e in entries]

RunResult

Result of processing one run with run_timeseries_statistics.

PlanetPostStats.TimeSeriesMeSd.output_entries — Method
output_entries(cfg::TimeSeriesConfig, rd::RunData) -> Vector{OutputEntry}

Assigns the variables of a run to the output file sets and vertical coordinates:

  • without cfg.pressure_levels: all variables in :main, 3D variables on model levels;
  • mode = :add: all variables in :main as above, plus every 3D variable with to_pressure = true on pressure levels in :pressure;
  • mode = :replace: all variables in :main, 3D variables with to_pressure = true on pressure levels, the other 3D variables on model levels.

The pressure-level fields are computed with interpolate_to_pressure from the monthly surface pressure cfg.pressure_levels.surface_pressure of the run.

Example

entries = output_entries(cfg, rd)
count(e -> e.vertical == :pressure, entries)

PlanetPostStats.TimeSeriesMeSd.process_runs — Method
process_runs(load, cfg::TimeSeriesConfig, runs) -> Vector{RunResult}

Processes the runs one after the other: rd = load(r) must return the RunData of run r, which is then processed with process_run(cfg, rd) and released before the next run is loaded. This is the entry point for applications that provide their own input (e.g. PlanetPostStats.DustOptics); run_timeseries_statistics uses it with load_run. cfg is not validated here.

Arguments

  • load: function run::String -> RunData.
  • cfg::TimeSeriesConfig: configuration of the statistics and the output.
  • runs: run identifiers.

Example

results = process_runs(r -> load_run(cfg, r), cfg, cfg.runs)

PlanetPostStats.TimeSeriesMeSd.run_timeseries_statistics — Method
run_timeseries_statistics(cfg::TimeSeriesConfig; runs=cfg.runs) -> Vector{RunResult}

Main entry point. Validates cfg and processes every run in runs (default: all runs of the configuration) sequentially:

  1. load_run reads the monthly scaleacc files and evaluates derived variables.
  2. With cfg.pressure_levels, the 3D variables with to_pressure = true are interpolated to pressure levels (interpolate_to_pressure), one variable at a time, and assigned to the output files (output_entries).
  3. For every variable, the monthly gridded field (ij), its zonal mean (zm), and its global mean (gm) are formed (planet_means); for each of the three, the requested products of ALL_PRODUCTS are computed (annual_means, seasonal_means, multiyear_stats, monthly_stats, all built on PlanetTools.PlanetStatistics) and written immediately, so that only one variable's results are held in memory.
  4. The run's data are released before the next run is loaded.

Output directory of run r: output_directory(cfg, r), with subdirectories MonthlyTs, AnnualTs, SeasonalTs, AnnualMeSd, SeasonalMeSd, MonthlyMeSd.

Statistics are computed only from periods lying entirely in cfg.stat_period; products for which no such period exists in a run (e.g. a run shorter than the window) are skipped with a warning.

Arguments

  • cfg::TimeSeriesConfig: configuration.

Keyword arguments

  • runs = cfg.runs: subset of runs to process.

Returns

Vector{RunResult}, one per run, with written file paths and summary tables (see annual_summary, seasonal_summary).

Example

using PlanetPostStats.TimeSeriesMeSd
results = run_timeseries_statistics(cfg)
annual_summary(results)
